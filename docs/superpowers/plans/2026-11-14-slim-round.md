# Slim Round (0.10.0, C API 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Work in the worktree `.worktrees/slim-round` (branch `slim-round`, from `main` at the 0.9.0 release); merge to `main` after Task 12 and remove the worktree (`git worktree remove .worktrees/slim-round`).

**Goal:** Turn group tactics into a small general core plus optional building blocks ("kit") with one lent rules object whose nine slots let a game plug in its own targets, columns, places, member costs, spot scores, triggers, aborts, channels and report kinds; and give the C and WebAssembly layers one shared implementation of every binding helper.

**Architecture:** `sagax_decide::group` keeps its core files; the shipped tactics, role bits, tags, shapes and every kit default (`impl Default` of `SquadConfig`, `CrewConfig`, `SkillTable`) move to a new `group::kit` module that only uses public core API; the core never names `kit` (source-scan test). The rules object is a Rust trait `SquadRules` (every method defaults to today's behaviour) lent per call through `_with` variants (`plan_with`, `check_with`, `Crew::tick_with`, …); the plain calls are exactly the `_with` calls with `BuiltInRules`, so a game that uses no slots never sees them. C gets `sx_squad_rules` (function pointers + `void *user`, `NULL` = built-in) and `_with` exports; JS gets no callbacks. A new internal crate `sagax-abi` holds the number codes and checked conversions shared by `sagax-ffi` and `sagax-wasm`.

**Tech Stack:** Rust 2024 workspace (rust-version 1.88), new crate `crates/sagax-abi` (internal, not re-exported), `sagax-ffi` (`include/sagax.h`), `sagax-wasm` + `js/sagax.mjs`, Node 22 tests via `js/run.sh`, C examples via `examples/c/run.sh` (GitHub CI only).

**Spec:** `docs/superpowers/specs/2026-11-14-slim-round-design.md` (approved). This plan decides its "Left to the builder" items in the section "Builder decisions" below.

## Builder decisions

- **Lending:** "takes the rules as an optional argument" is done as a second function, not an `Option` parameter: `Squad::plan_with(.., rules: &mut dyn SquadRules)`, `check_with`, `signal_with`, `reinstate_with`, `report_arrives_at_with`, `Crew::tick_with`, `Crew::reinstate_with`, `Crew::report_with`; C `sx_squad_plan_with`, `sx_squad_check_with`, `sx_squad_signal_with`, `sx_squad_reinstate_with`, `sx_squad_report_arrives_at_with`, `sx_crew_tick_with`, `sx_crew_reinstate_with`, `sx_crew_report_with` (each takes `const sx_squad_rules *rules`, `NULL` = built-in). The plain names stay and equal `_with(&mut BuiltInRules)`, so existing call sites, tests and examples do not change. `signal`/`reinstate`/`report_arrives_at` need `_with` forms because they send over a channel outside `plan`/`check`.
- **Plain calls on a squad that needs rules** (`Squad::needs_rules()`: a tactic uses `Place::Custom`, `Trigger::Custom` or `Abort::Custom`, a member has `Channel::Custom`, or `rule_columns > 0`): `plan`/`check`/`Crew::tick` return `Err(PlanError::NeedsRules)`; `orders_due`/`arrived`/`reinstate` never activate a due plan (activation waits for the next `_with` call; times still count from `active_at`) and queue no order over a custom channel; `signal` returns false. Fails loudly instead of losing orders.
- **Custom ids:** one id space per slot (`Place::Custom(u32)`, `Trigger::Custom(u32)`, `Abort::Custom(u32)`, `Channel::Custom(u32)`), any `u32`, never interpreted by the core. Report kinds: the core keeps 1, 2, 4; every other kind goes to the report slot; `REPORT_GAME_FIRST = 16` is documented as the first kind a game should use (kinds below may gain a core meaning later).
- **Fallbacks inside `BuiltInRules`** (only reachable through `_with(&mut BuiltInRules)` or a C struct with a `NULL` pointer): `Place::Custom` → the leader's position (as `Place::Here`), `Trigger::Custom` and `Abort::Custom` → never, `Channel::Custom` → never arrives.
- **Squad view:** `SquadView<'a>` (read-only, built by the core from `&Squad`, positions converted by a hex `Crew`); C: opaque `const sx_squad_view *` with read-only `sx_view_*` accessors (calls on the view, never on the squad).
- **Module paths:** core stays in `crates/sagax-decide/src/group/{squad,orders,tactic,spots,crew,keeper,members,skill}.rs` plus new `rules.rs` (`pub mod rules`: trait, contexts, view, report actions, built-in helpers); kit in `crates/sagax-decide/src/group/kit/{mod.rs,tactics.rs,roles.rs,tags.rs,defaults.rs}`; `group` re-exports kit names where they are today (`group::tactics`, `ROLE_*`, `TAG_*`, `Shape`, `IN_RANGED`, `IN_AREA`), so `sagax::prelude::*` and every import keep working.
- **Core-vs-kit check:** test `core_does_not_import_kit` (`group/layout_tests.rs`) reads every `.rs` file of `src/group/` via `std::fs::read_dir(concat!(env!("CARGO_MANIFEST_DIR"), "/src/group"))`, and for every file that is not under `kit/`, not `mod.rs` and not a `*tests.rs` file asserts the source contains no `kit`; it also asserts the list of core files equals the fixed list above (a new core file must be added on purpose). Kit defaults live in `kit/defaults.rs`; `Squad::new` reads its table from `SquadConfig::skill_table`, so the core never calls a kit default.
- **Role columns:** the role list sits in `SquadConfig::roles: RoleCounts` (≤ 8 masks). Role column 0 and 1 keep their places 4 and 5 (`IN_ROLE_0`, `IN_ROLE_1`; kit `IN_RANGED = IN_ROLE_0`, `IN_AREA = IN_ROLE_1`); roles 2.. follow after column 7; `Squad::extra_start() = 8 + roles.len().saturating_sub(2)`. With the default list every row and every `IN_*` number is today's (the design's "default rows are unchanged" and a movable role list only fit together this way). Fewer than two roles: the free columns read 0.
- **Rule columns:** `SquadConfig::rule_columns` columns follow the caller's extra columns: row = built-in | roles 2.. | extra | rule columns; `Squad::rule_start() = extra_start() + extra_columns`.
- **Costs and scores** are `i128` in Rust (exactly today's `distance` values, so the built-in path is identical), `int64_t` in C (the context's `built_in` saturates). Spot ranking key: `(score, index)`; built-in score `spot_score_builtin = (miss as i128) << 100 | distance`, which orders exactly like today's `(miss, distance, index)` at `spots.rs:221-226`.
- **Call order (documented in `rules.rs`):** in a plan: targets (knowledge order) → per candidate in candidate order: columns, then custom aborts in list order (stop at the first that fires) → place (slots in order, gather before place) → member cost (slot-major, members in group order, computed once into a scratch matrix) → spot score (members in assignment order; gather spots then place spots, spots in index order). In a check: report (arrival order) → report actions → columns/abort of the active row → candidates as in a plan → trigger. Channel: per goal in plan goal order.
- **Squad decider "tracing":** a score log (`Squad::set_score_log`, `score_log() -> &[ScoreEntry]`), since the squad scores with `Decider::score`, not `decide_traced`; plus `decider()`/`decider_mut()` and C/JS lent decider handles. `PlanError::OptionsChanged` when the option count no longer equals the tactic count.
- **Helpers:** `BuiltInRules` (unit struct, all defaults) instead of a struct of closures; contexts carry the built-in value (`CostCtx::built_in`, `SpotCtx::built_in`) so wrapping is one addition; Rust `spot_score_builtin`, C `sx_spot_score_builtin`, `sx_squad_rules_default`; path cost: Rust `sagax::rules::{path_cost, PathCost}`, C `sx_path_cost`. Small extra helper for the proof: `Crew::report(_with)` (a game report over the member's channel), Rust, C and JS (plain).

- Public repo: no game names, no private paths, English, author noreply.
