# API Round (0.9.0, C API 9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Sagax look like one library from the outside: bridges between navigation and the AI blocks, member-side helpers, the `Crew` convenience layer, one set of conventions in Rust, C and JS, and a beginner path in the docs.

**Architecture:** Shared types (`Pos`, `Cell`, `HexLayout`) move to `sagax-core`, so `sagax-nav` and `sagax-decide` meet without depending on each other. The `Crew` lives in `sagax-decide::group` and only calls public `Squad` / `GoalKeeper` API, so every step stays doable by hand. C (`sagax-ffi`) and WASM (`sagax-wasm` + `js/sagax.mjs`) only translate; a new umbrella crate `sagax` re-exports everything with a prelude.

**Tech Stack:** Rust 2024 workspace (rust-version 1.88), `sagax-ffi` (`include/sagax.h`), `sagax-wasm` (no wasm-bindgen) + `js/sagax.mjs`, Node 22 tests via `js/run.sh`, C examples via `examples/c/run.sh` (GitHub CI only).

**Spec:** `docs/superpowers/specs/2026-11-13-api-round-design.md` — its section "Decisions after review" overrides earlier text (no `Metric::HexOffset`, no `Message::danger`, walking distance A5 deferred, no default rules).

## Global Constraints

- Integer only, caller time and seed, wrap-safe, documented tie-breaks.
- Fixed capacities; no allocation in searches; "no allocation after warm-up except one Vec per plan" stays the claim for the squad.
- Every block in Rust, C and JS; square and hex.
- Public repo: no game names, no private paths, English, author noreply.
- Identical results before and after the round for the same inputs (existing scene tests keep their tick numbers unless a test was wrong).
- A break must fail to compile, or fail loudly, never change behaviour quietly. Keep old names as deprecated aliases where cheap (C macros, JS method aliases, Rust `#[deprecated]` forwarders), for 0.9 only.
- Commits: author `STARSCrazy <STARSCrazy@users.noreply.github.com>` from the repo git config (already set; do not override), English messages, one commit per task, trailers as the executing session prescribes. Stage paths explicitly (`git add crates js examples docs README.md CHANGELOG.md Cargo.toml Cargo.lock`), never `git add -A` (`.worktrees/` is untracked).
- CI per task, all green before commit: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `sh js/run.sh`. C examples (`sh examples/c/run.sh`) run only on GitHub CI (no local C compiler): every task that changes a C signature updates `examples/c/*.c` in the same task; the header/export test from Task 1 is the local proxy.
- Version stays 0.8.0 / `API_VERSION = 8` until Task 14, which bumps to 0.9.0 / 9.
- Time-argument rule used in this plan (resolves the spec's convention against the anti-goal, see Task 1): `now` comes right after the handle and the ids that name what the call addresses (`reinstate(id, now)`, `timers.set(id, now, d)`); payloads come after `now`; `seed` is the last input, out-params follow it.
